# Civil Solution Website

Civil Solution is a bilingual React website for a civil and structural engineering consultancy serving clients across Bangladesh with its head office in Chattogram. The project is a **portable, frontend-only React/Vite application** intended for manual development in VS Code. It does not require a database, backend API, authentication service, tRPC, Drizzle, or platform-specific runtime.

## Technology

The application uses React 19, TypeScript, Vite, React Router DOM, Tailwind CSS 4, DaisyUI, Lucide React, and Vitest. The visual system is the project’s Warm Technical Atelier direction: a cream paper canvas, structural brown typography, turquoise action states, editorial section labels, architectural button details, restrained motion, and responsive layouts.

## Requirements

Install Node.js 20 or newer and pnpm. From the project root, install dependencies and start the development server:

```bash
pnpm install
pnpm dev
```

Vite serves the app locally at the URL shown in the terminal. This project does not require a platform preview URL, special hostname allowlist, hosted environment variable, or external service for local development. The production workflow is:

```bash
pnpm check
pnpm test
pnpm build
pnpm preview
```

The build output is written to `dist/` and is generated by Vite from the `client/` application root.

## Routing

React Router provides the following routes:

```text
 /                         Homepage
/services/:slug           Service detail page
/admin/login              Admin login
/admin                    Protected inquiry dashboard
*                         Redirects to the homepage
```

Service records are maintained in `client/src/content/services.json`. To add a service, add its bilingual record, slug, image metadata, and related-service references in the catalog, then confirm that the corresponding detail fallback and image mapping are appropriate in `ServiceDetail.tsx`.

## Bilingual behavior

The navigation language toggle controls English and Bengali content across the homepage and service pages. The selected language is stored in `localStorage` under `civil-language`, so the choice persists between routes and browser refreshes. When editing content, maintain both `en` and `bn` fields and check long Bengali strings at mobile widths.

## Contact behavior

The inquiry form validates the visitor’s name, phone number, and project message, while email remains optional. When Supabase is configured, it stores the inquiry in the protected `public.inquiries` table and visitors can also open a prefilled Gmail compose window or continue through WhatsApp. When Supabase is not configured, the previous handoff behavior remains available with a setup warning.

The map link and WhatsApp number are configured in the contact content. The site presents Bangladesh-wide service coverage and the Chattogram head office; review the firm’s approved phone number, email address, and exact office location before handing the project to a client.

## Content and image safety

Project stories contain work descriptions only and avoid client identities, private addresses, and confidential deal information. Do not add fabricated testimonials, ratings, client names, or unsupported project claims. Image credits and source links should remain with their associated service or project record when an externally sourced image is used.

## Supabase inquiry system

The website supports a public inquiry form backed by Supabase and a protected admin inbox at `/admin`.

1. Create a Supabase project.
2. Run [`supabase/migrations/20260917000000_create_inquiries.sql`](./supabase/migrations/20260917000000_create_inquiries.sql) in the Supabase SQL Editor.
3. Add the following variables to local `.env.local` and to the Netlify/Vercel project environment settings. Never commit this file.

```bash
VITE_SUPABASE_URL=https://your-project-ref.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=your-publishable-key
```

The publishable key is safe for the browser when Row Level Security is enabled. Do not expose a Supabase `service_role` key in the frontend.

4. Create the admin user in Supabase Authentication.
5. Assign the admin role using the Supabase SQL Editor, replacing the email with the exact admin email:

```sql
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb) || '{"role":"admin"}'::jsonb
where email = 'admin@example.com';
```

6. Sign in at `/admin/login`. The dashboard only accepts an authenticated user whose `app_metadata.role` is `admin`.

The inquiry table allows anonymous visitors to insert a request, while only admin-role authenticated users can read or update inquiry status. RLS policies and grants are defined together in the migration file.

Without the Supabase variables, the public site remains usable and shows a setup warning when someone submits the inquiry form; submissions are not persisted until the variables and migration are configured.


## Email notifications

The repository includes `supabase/functions/notify-inquiry/index.ts`. Deploy it as a Supabase Edge Function and configure a Database Webhook for `INSERT` events on `public.inquiries`. Set these Edge Function secrets: `RESEND_API_KEY`, `ADMIN_NOTIFICATION_EMAIL`, `NOTIFICATION_FROM_EMAIL`, and `WEBHOOK_SECRET`. Configure the webhook to send the same secret in the `x-webhook-secret` header. The function sends an immediate email containing the inquiry details and never exposes provider credentials to the browser.

## Careers forum

The public careers forum is available at `/careers` and is linked from the footer. It lists only active records from `public.career_posts`. When there are no active records, it explicitly states in English and Bengali that Civil Solution is not hiring at the moment. Admins can create, edit, activate/deactivate, and delete bilingual job posts from `/admin` after running `supabase/migrations/20260917010000_create_career_posts.sql`.

## Admin inquiry search

The admin inbox supports text search across name, phone, email, service, and message, plus status and service filters. Submission feedback includes a disabled loading state, success toast, and error toast with the form left available for retry.


## Dedicated inquiry and blog pages

The protected inquiry manager is available at `/admin/inquiries` with search, service/status filters, and status updates. The public bilingual blog is available at `/blog`, while admins manage draft and published posts at `/admin/blog`. Run `supabase/migrations/20260918000000_create_blog_posts.sql` in the Supabase SQL Editor before creating or publishing blog posts. Published posts are public; drafts remain visible only to admin-role users.
